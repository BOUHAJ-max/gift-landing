بيئات Python الافتراضية: venv وإدارة المكتبات

تعلم إنشاء بيئة Python افتراضية وتفعيلها وتثبيت المكتبات وتجميد المتطلبات لتجنب تعارض المشاريع.

دليل تقني عملي•إعداد: Mohamed Bouhaj•BOUHAJ TECH

محتويات المقال

1. لماذا نستخدم venv؟2. إنشاء البيئة3. تفعيل البيئة4. تثبيت المكتبات5. حفظ الاعتماديات6. حماية المستودع7. حل مشكلات البيئة8. مشروع قابل لإعادة الإنشاء

قد يحتاج كل مشروع Python إلى إصدارات مكتبات مختلفة. تساعد البيئة الافتراضية على عزل الاعتماديات ومنع تداخلها مع مشاريع أخرى أو مع تثبيت Python العام.

1. لماذا نستخدم venv؟

تثبيت كل المكتبات في بيئة واحدة قد يسبب تعارض الإصدارات. تنشئ venv مجلداً يحتوي أدوات Python الخاصة بالمشروع، وتبقي الاعتماديات منفصلة عن المشاريع الأخرى.

2. إنشاء البيئة

انتقل إلى مجلد المشروع وأنشئ بيئة باسم .venv:
mkdir my-python-app
cd my-python-app
python -m venv .venv

إذا لم تكن وحدة venv متاحة في بيئتك، راجع توثيق توزيع Python أو طريقة تثبيت الحزم الخاصة بنظامك.

3. تفعيل البيئة

في Linux وmacOS وبيئات Termux المعتادة:
source .venv/bin/activate

في Windows PowerShell يختلف أمر التفعيل. عند نجاح التفعيل يظهر غالباً اسم البيئة في بداية سطر الطرفية. استخدم python -m pip لضمان تثبيت المكتبة في المفسر النشط.

4. تثبيت المكتبات

حدّث pip ثم ثبت المكتبة التي يحتاجها مشروعك:
python -m pip install --upgrade pip
python -m pip install requests

راجع اسم الحزمة ومصدرها وإصداراتها قبل التثبيت، وتجنب تشغيل سكربتات تثبيت مجهولة المصدر بصلاحيات مرتفعة.

5. حفظ الاعتماديات

سجّل المكتبات المثبتة في ملف متطلبات:
python -m pip freeze > requirements.txt

على جهاز آخر يمكن تثبيتها باستخدام python -m pip install -r requirements.txt. راجع الملف قبل نشره حتى لا يتضمن اعتماديات غير لازمة.

6. حماية المستودع

لا ترفع مجلد البيئة .venv إلى Git؛ فهو كبير ويمكن إعادة إنشائه. أضف إلى .gitignore:
.venv/
__pycache__/
*.pyc
.env

ملف .env قد يحتوي مفاتيح وأسراراً؛ لا ترفعه إلى مستودع عام. احتفظ بنموذج آمن مثل .env.example دون قيم سرية.

تمرين: أنشئ مشروعاً وبيئة افتراضية، ثبت requests، احفظ requirements.txt، ثم اكتب خطوات إعادة إنشاء البيئة في README.

7. حل مشكلات البيئة الافتراضية

إذا ظهرت رسالة تفيد بأن مكتبة غير موجودة رغم تثبيتها، فتحقق من أن الطرفية تستخدم المفسر نفسه الذي ثبّتت فيه الحزمة:

which python
python --version
python -m pip --version
python -m pip show requests

استخدام python -m pip يقلل الالتباس بين أكثر من تثبيت لـPython أو pip. إذا لم يظهر اسم البيئة في الطرفية، أعد تفعيلها من مسار المشروع. وإذا انتقلت بالمشروع إلى جهاز آخر، أنشئ البيئة من جديد بدلاً من نسخ مجلد .venv.

عند تعارض الإصدارات، راجع رسائل pip وسجّل إصدار Python وإصدارات المكتبات. لا تحذف ملفات البيئة قبل التأكد من أن ملفات المشروع وملف المتطلبات محفوظة.

8. مشروع قابل لإعادة الإنشاء

اجعل هيكل المشروع واضحاً، مثلاً:

my-project/
├── .venv/
├── .gitignore
├── requirements.txt
├── README.md
└── app.py

ضع .venv/ وملفات الأسرار في .gitignore، ثم اشرح في README كيفية إعداد بيئة جديدة:

python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python app.py

هذه أوامر مناسبة لبيئات Linux/macOS وTermux المعتادة؛ يحتاج Windows إلى صيغة تفعيل مختلفة. اختبر التعليمات في مجلد نظيف أو جهاز آخر قبل اعتبار المشروع قابلاً لإعادة الإنتاج.

مهمة: اطلب من شخص آخر اتباع README دون مساعدتك. دوّن الخطوات غير الواضحة وعدّل الدليل حتى ينجح تشغيل المشروع.

تعلم هذه المفاهيم بالتدرج وطبّق الأمثلة داخل بيئة تملكها. راجع التوثيق الرسمي للأدوات قبل استخدامها في بيئة إنتاجية.
